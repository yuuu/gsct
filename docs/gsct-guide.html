STEP-BY-STEP GUIDE

Rustで作る git status shortcuts ツール 手順書

Oct 15, 2026 · @Yuhei Okazaki

はじめに

この手順書に沿ってStep 0〜10 を進めると、scm_breeze の Git Status Shortcuts と Git の alias を Rust で再実装した CLI gsct が完成します。最初にフォーマッタと CI を整え、以降はテストファーストで動くものを作りながら、Rust の基礎を The Rust Programming Language 日本語版（以下「Rust Book」）と行き来して学べる構成です。

完成イメージ

$ gs
# On branch: main  |  +1
#
➤ Changes to be committed
#
#        modified: [1] src/main.rs
#
➤ Changes not staged for commit
#
#        modified: [2] src/status.rs
#
➤ Untracked files
#
#       untracked: [3] memo.txt
#

$ ga 2-3          # => git add src/status.rs memo.txt
$ gd 1            # => git diff src/main.rs
$ ge vim 1        # => vim src/main.rs（任意のコマンドで番号を使える）
$ gsct aliases     # alias 一覧（scm_breeze の git_aliases 相当）

設計の方針（これまでの相談で決めたこと）

  • シェル関数・シェル変数（$e1 など）は使わない。git や ls などの既存コマンドも一切上書きしない。
  • gs を実行すると、番号とファイルの対応を .git/gsct-status に保存する。ga 1 などはそれを読んで番号をパスに展開し、本物の git を呼ぶ。
  • alias は2通りで使える。
    • gsct gd 1 のようにサブコマンドとして使う。
    • gsct install-links ~/.local/bin で gd などのシンボリックリンクを作り、gd 1 と直接打つ。既存コマンドと名前がぶつかる場合は作らない。
  • ツール名は gsctとします。gs は Ghostscript と衝突するので本体名には使いません。別の名前にしたい場合は、Step 1 の --name と、手順中の gsct をすべて置き換えてください。

進め方

  1. 各ステップの冒頭にある Rust Book の該当ページ を先に読みます。全部を理解できなくても大丈夫です。
  2. Step 3 以降は テストファースト で進めます。毎回次のサイクルを回します。
    1. Red：先にテストを書き、中身が todo!() だけの関数を用意して cargo test を実行し、失敗することを確認してコミットします。
    2. Green：テストが通るように実装し、mise run ci が通ったらコミットします。
    3. Refactor：テストが通ったまま、読みやすく整えます（任意）。
  3. 手順書のコードを コピペせずに手で打つ のがおすすめです。打ち間違えたときのコンパイルエラーを読むことが、いちばんの練習になります。
  4. 「やってみよう」は任意の練習問題です。飛ばしても次のステップに進めます。

ブランチとコミットの運用

Step 1 だけは main に直接コミットします。Step 2 以降は、次の流れを毎回繰り返します。コマンド中のブランチ名・コミットメッセージ・PR タイトルは、各ステップにそのままコピペできる形で載せています。

# 1. ステップ開始時：main を最新にしてブランチを切る
git switch main && git pull
git switch -c <ブランチ名>

# 2. Red / Green ごとにコミット（各ステップ記載のメッセージを使う）
git add -A
git commit -m "<コミットメッセージ>"

# 3. ステップ完了時：CI と同じチェックを手元で通してから push し、PR を作る
mise run ci
git push -u origin <ブランチ名>
gh pr create --base main --title "<PRタイトル>" --body "<説明>"

# 4. CI が通るのを待ってからマージする（Step 2 以降）
gh pr checks --watch

git switch main && git pull

コミットメッセージは Conventional Commits 形式（feat: 機能追加、test: テスト、chore: 雑務、ci: CI 設定、docs: 文書、style: 整形）の英語で統一しています。

手順 1：フォーマッタの設定を置く

プロジェクト直下に rustfmt.toml を作ります。

# Rust 2024 のフォーマットスタイルを使う
style_edition = "2024"

rustfmt は設定がなくても動きます。ただしファイルを置いておくと、「このリポジトリは rustfmt で整形する」ことが明示され、後から設定を足す場所にもなります。

Zed は保存時に自動でフォーマットします（format_on_save は既定で有効）。Rust では rust-analyzer 経由で rustfmt が使われ、rustfmt.toml の設定もそのまま反映されます。手動で整形するときは cargo fmt を実行します。

手順 2：mise にチェック用のタスクを登録する

Step 1 でできた mise.toml を次の内容にします。

[tools]
rust = { version = "1.98.1", components = "rustfmt,clippy" }

[tasks.fmt]
description = "フォーマットを確認する"
run = "cargo fmt --check"

[tasks.lint]
description = "clippy で静的解析する（警告もエラー扱い）"
run = "cargo clippy --all-targets -- -D warnings"

[tasks.test]
description = "テストを実行する"
run = "cargo test"

[tasks.ci]
description = "CI と同じチェックをまとめて実行する"
depends = ["fmt", "lint", "test"]
  • components で rustfmt と clippy を明示します。CI（mise-action）では Rust が最小構成でインストールされ、指定しないと cargo fmt と cargo clippy が 'cargo-fmt' is not installed for the toolchain のエラーで失敗します。
  • --all-targets を付けると、テストコードも clippy の対象になります。
  • -D warnings は「警告をエラーとして扱う」指定です。未使用の関数や変数が残っていると CI が落ちるので、各ステップの終わりには必ず警告ゼロになります。
  • depends で指定したタスクは、mise run ci の実行時にまとめて動きます。
  • ここで書いたタスクを手元と CI の両方で使うので、「手元では通るのに CI で落ちる」というずれが起きにくくなります。
mise tasks      # 登録されたタスクの一覧
mise run ci     # 全部通れば OK

mise trust を求められた場合は、表示どおりに mise trust を実行してください。

git add -A
git commit -m "chore: add rustfmt config and mise tasks"

手順 3：GitHub Actions のワークフローを作る

.github/workflows/ci.yml を作ります。

name: CI

  push:

src/main.rs の末尾（fn main の後ろ）に、テストだけを追加します。

#[cfg(test)]
mod tests {
    use std::path::PathBuf;

    use clap::{CommandFactory, Parser};

    use super::*;

    #[test]
    fn cli_definition_is_valid() {
        Cli::command().debug_assert();
    }

    #[test]
    fn unknown_subcommand_is_treated_as_alias() {
        let cli = Cli::try_parse_from(["gsct", "gd", "1", "--cached"]).unwrap();
        let Command::Alias(args) = cli.command else {
            panic!("alias として解釈されていません");
        };
        assert_eq!(args, ["gd", "1", "--cached"]);
    }

    #[test]
    fn exec_keeps_hyphen_arguments() {
        let cli = Cli::try_parse_from(["gsct", "exec", "ls", "-l", "1"]).unwrap();
        let Command::Exec { args } = cli.command else {
            panic!("exec として解釈されていません");
        };
        assert_eq!(args, ["ls", "-l", "1"]);
    }

    #[test]
    fn install_links_accepts_comma_separated_skip() {
        let cli =
            Cli::try_parse_from(["gsct", "install-links", "/tmp/bin", "--skip", "gs,gm"]).unwrap();
        let Command::InstallLinks { dir, force, skip } = cli.command else {
            panic!("install-links として解釈されていません");
        };
        assert_eq!(dir, PathBuf::from("/tmp/bin"));
        assert!(!force);
        assert_eq!(skip, ["gs", "gm"]);
    }
}
  • #[cfg(test)] が付いたモジュールは cargo test のときだけコンパイルされます。use super::*; で親モジュール（main.rs）の非公開の型も使えます。
  • try_parse_from は、本物のコマンドライン引数の代わりに、渡した配列を解析します。テストではこれで「こう打ったら、こう解釈される」を確かめます。
  • let Command::Alias(args) = cli.command else { panic!(...) }; は、「Alias なら中身を args に取り出し、それ以外ならテスト失敗」という書き方です（let-else）。
  • Cli::command().debug_assert() は clap が用意している自己診断です。引数定義の矛盾を検出します。

Green：CLI の型を定義する

src/main.rs の fn main() { ... } を消し、代わりに次のコードをファイルの先頭に置きます（#[cfg(test)] 以降はそのまま）。

use std::path::PathBuf;
use std::process;

use anyhow::Result;
use clap::{Parser, Subcommand};

/// scm_breeze 風の git status shortcuts と git alias
#[derive(Parser)]
#[command(version, about)]
struct Cli {
    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    /// 番号付きで git status を表示する（gs）
    Status,
    /// 番号をファイルパスに展開して任意のコマンドを実行する（ge）
    Exec {
        /// 実行するコマンドと引数
        #[arg(required = true, trailing_var_arg = true, allow_hyphen_values = true)]
        args: Vec<String>,
    },
    /// alias の一覧を表示する
    Aliases,
    /// alias 名のシンボリックリンクを作成する
    InstallLinks {
        /// リンクを作成するディレクトリ（例: ~/.local/bin）
        dir: PathBuf,
        /// 既存のコマンドと名前が衝突しても作成する
        #[arg(long)]
        force: bool,
        /// 作成しない alias 名（カンマ区切り。例: --skip gs,gm）
        #[arg(long, value_delimiter = ',')]
        skip: Vec<String>,
    },
    /// alias を実行する（例: gsct gd 1）
    #[command(external_subcommand)]
    Alias(Vec<String>),
}

fn main() {
    match run() {
        Ok(code) => process::exit(code),
        Err(err) => {
            eprintln!("gsct: {err:#}");
            process::exit(1);
        }
    }
}

fn run() -> Result<i32> {
    let cli = Cli::parse();
    match cli.command {
        Command::Status => println!("TODO: status"),
        Command::Exec { args } => println!("TODO: exec {args:?}"),
        Command::Aliases => println!("TODO: aliases"),
        Command::InstallLinks { dir, force, skip } => {
            println!("TODO: install-links {dir:?} force={force} skip={skip:?}")
        }
        Command::Alias(args) => println!("TODO: alias {args:?}"),
    }
    Ok(0)
}

コードの読み方

  • use は他の場所にある型や関数を短い名前で使うための宣言です（7.4）。
  • #[derive(Parser)] は「この構造体に対して、引数解析のコードを自動生成して」という指示です。/// のコメントがそのまま --help の説明文になります。
  • enum Command の各バリアントがサブコマンドになります。InstallLinks は自動的に install-links という名前になります。
  • #[command(external_subcommand)] は「定義されていないサブコマンドは全部ここで受け取る」という意味です。テストのとおり gsct gd 1 --cached は Alias(["gd", "1", "--cached"]) になります。
  • run() は Result<i32> を返します。成功なら Ok(終了コード)、失敗なら Err(エラー) です。main() でそれを match し、エラーなら標準エラーに表示して終了コード1で終了します。

確認

テストが4件とも通り、TODO: alias ["gd", "1", "--cached"] と表示されれば OK です。cargo run -- <引数> の -- より後ろが、作ったプログラムに渡されます。

やってみよう：「gsct exec を引数なしで実行するとエラーになる」ことを確かめるテストを追加してみましょう。ヒント：Cli::try_parse_from(["gsct", "exec"]).is_err() を assert! します。通ったら、required = true を消すとそのテストが失敗することも確かめます（確認後は元に戻す）。

  • 1行目は ## で始まるブランチ情報です。
  • 2行目以降は XY パス の形式です。X はステージ済みの状態、Y はワークツリーの状態です（M 変更、A 追加、D 削除、R リネーム、?? 未追跡、UU などはコンフリクト）。

use std::process::Command;

use anyhow::{Context, Result, bail};

/// git コマンドを実行し、標準出力を文字列で返す
pub fn output(args: &[&str]) -> Result<String> {
    let out = Command::new("git")
        .args(args)
        .output()
        .context("git を実行できませんでした")?;

    if !out.status.success() {
        let stderr = String::from_utf8_lossy(&out.stderr);
        bail!("git {} が失敗しました: {}", args.join(" "), stderr.trim());
    }

    Ok(String::from_utf8_lossy(&out.stdout).into_owned())
}

/// `git status --porcelain -b -z` の出力を解析する
pub fn parse(output: &str) -> Status {
    let mut status = Status::default();
    let mut fields = output.split('\0');

    while let Some(field) = fields.next() {
        // 先頭の "## " で始まる項目はブランチ情報
        if let Some(branch_line) = field.strip_prefix("## ") {
            parse_branch(branch_line, &mut status);
            continue;
        }

        // それ以外は "XY パス" の形式（X = ステージ、Y = ワークツリーの状態）
        let mut chars = field.chars();
        let (Some(x), Some(y)) = (chars.next(), chars.next()) else {
            continue;
        };
        let Some(path) = field.get(3..) else {
            continue;
        };

        // リネーム・コピーの場合は、次の項目に元のパスが入っているので読み飛ばす
        if x == 'R' || x == 'C' {
            fields.next();
        }

        status.entries.extend(classify(x, y, path));
    }

    status
}

/// ブランチ情報を解析する
/// 例: "main...origin/main [ahead 1, behind 2]"、"No commits yet on main"
fn parse_branch(line: &str, status: &mut Status) {
    let line = line.strip_prefix("No commits yet on ").unwrap_or(line);

    let (name, tracking) = match line.split_once(" [") {
        Some((name, tracking)) => (name, tracking.trim_end_matches(']')),
        None => (line, ""),
    };

    status.branch = match name.split_once("...") {
        Some((local, _remote)) => local.to_string(),
        None => name.to_string(),
    };

    for item in tracking.split(", ") {
        if let Some(n) = item.strip_prefix("ahead ") {
            status.ahead = n.parse().unwrap_or(0);
        } else if let Some(n) = item.strip_prefix("behind ") {
            status.behind = n.parse().unwrap_or(0);
        }
    }
}

/// XY の2文字から、どのグループのどの変更かを判定する
/// 1つのファイルが「ステージ済み」と「未ステージ」の両方に入ることもあるので Vec で返す
fn classify(x: char, y: char, path: &str) -> Vec<Entry> {
    // コンフリクト中のファイル
    let unmerged = match (x, y) {
        ('D', 'D') => Some(Kind::BothDeleted),
        ('A', 'U') => Some(Kind::AddedByUs),
        ('U', 'D') => Some(Kind::DeletedByThem),
        ('U', 'A') => Some(Kind::AddedByThem),
        ('D', 'U') => Some(Kind::DeletedByUs),
        ('A', 'A') => Some(Kind::BothAdded),
        ('U', 'U') => Some(Kind::BothModified),
        _ => None,
    };
    if let Some(kind) = unmerged {
        return vec![Entry::new(Group::Unmerged, kind, path)];
    }

    // 未追跡のファイル
    if x == '?' && y == '?' {
        return vec![Entry::new(Group::Untracked, Kind::Untracked, path)];
    }

    let mut entries = Vec::new();

    // X: ステージ済みの変更
    let staged = match x {
        'M' => Some(Kind::Modified),
        'A' => Some(Kind::NewFile),
        'D' => Some(Kind::Deleted),
        'R' => Some(Kind::Renamed),
        'C' => Some(Kind::Copied),
        'T' => Some(Kind::TypeChange),
        _ => None,
    };
    if let Some(kind) = staged {
        entries.push(Entry::new(Group::Staged, kind, path));
    }

    // Y: まだステージしていない変更
    let unstaged = match y {
        'M' => Some(Kind::Modified),
        'D' => Some(Kind::Deleted),
        'T' => Some(Kind::TypeChange),
        _ => None,
    };
    if let Some(kind) = unstaged {
        entries.push(Entry::new(Group::Unstaged, kind, path));
    }

    entries
}

コードの読み方

  • Option は「値がある（Some）か、ない（None）か」を表す型です。strip_prefix や split_once は、見つからなければ None を返します。
  • if let Some(x) = ... は「Some のときだけ中身を取り出して処理する」、let Some(x) = ... else { continue; }; は「None なら抜ける」という書き方です。
  • match (x, y) のように、タプルでまとめて分岐できます。_ は「それ以外全部」です。
  • &mut Status は「変更できる参照」です。呼び出し側の status を直接書き換えます。
  • fields.next() をループ内でも呼ぶと「1つ読み飛ばす」ことになります。for ではなく while let を使っているのはこのためです（13.2 イテレータ）。

/// 文字に色を付ける（color が false なら何もしない）
struct Painter {
    enabled: bool,
}

impl Painter {
    fn paint(&self, code: &str, text: &str) -> String {
        if self.enabled {
            format!("\x1b[{code}m{text}\x1b[0m")
        } else {
            text.to_string()
        }
    }
}

/// 表示用の文字列と、番号順に並べたファイルの絶対パスの一覧を作る
pub fn render(status: &Status, root: &Path, cwd: &Path, color: bool) -> (String, Vec<PathBuf>) {
    let p = Painter { enabled: color };
    let mut out = String::new();
    let mut files = Vec::new();

    // リモートとのコミット差分（例: "-2/+1"）
    let mut diff = Vec::new();
    if status.behind > 0 {
        diff.push(format!("-{}", status.behind));
    }
    if status.ahead > 0 {
        diff.push(format!("+{}", status.ahead));
    }
    let diff = if diff.is_empty() {
        String::new()
    } else {
        format!(
            "  {}  {}",
            p.paint("2;37", "|"),
            p.paint("0;33", &diff.join("/"))
        )
    };

    let header = format!(
        "{} On branch: {}{}",
        p.paint("2;37", "#"),
        p.paint("1", &status.branch),
        diff
    );

    if status.entries.is_empty() {
        let clean = p.paint("0;32", "No changes (working directory clean)");
        out.push_str(&format!("{header}  {}  {clean}\n", p.paint("2;37", "|")));
        return (out, files);
    }

    out.push_str(&format!("{header}\n{}\n", p.paint("2;37", "#")));

    // 10件以上あるときは番号の桁をそろえる
    let width = status.entries.len().to_string().len();

    for group in Group::ALL {
        let entries: Vec<&Entry> = status.entries.iter().filter(|e| e.group == group).collect();
        if entries.is_empty() {
            continue;
        }

        let hash = p.paint(&format!("0;{}", group.color()), "#");
        let arrow = p.paint(&format!("1;{}", group.color()), "➤");
        out.push_str(&format!("{arrow} {}\n{hash}\n", group.heading()));

        for entry in entries {
            let absolute = root.join(&entry.path);
            let relative = pathdiff::diff_paths(&absolute, cwd).unwrap_or(absolute.clone());
            files.push(absolute);

            let label = p.paint(entry.kind.color(), &format!("{:>15}", entry.kind.label()));
            let number = format!(
                "{}{:>width$}{}",
                p.paint("2;37", "["),
                files.len(),
                p.paint("2;37", "]")
            );
            let path = p.paint(
                &format!("0;{}", group.color()),
                &relative.display().to_string(),
            );
            out.push_str(&format!("{hash} {label}: {number} {path}\n"));
        }

        out.push_str(&format!("{hash}\n"));
    }

    (out, files)
}

コードの読み方

  • Path と PathBuf の関係は、&str と String の関係と同じです。借りるだけなら &Path、所有するなら PathBuf を使います。
  • let diff = ... を2回書いているのは「シャドーイング」です。同じ名前で別の型の変数を作り直せます（3.1 変数と可変性）。
  • {:>15} は「15文字幅で右寄せ」、{:>width$} は幅を変数 width で指定する書き方です。
  • .iter().filter(|e| e.group == group).collect() は「全件を順に見て、条件に合うものだけを Vec に集める」という意味です。|e| ... がクロージャ（無名関数）です。
  • 出力先が端末でないとき（gs | less など）は is_terminal() が false になり、色の制御文字を出しません。
  • _files のように _ で始まる変数名にすると「使っていない」という警告が出ません。Step 6 で使います。

/// ファイル一覧を NUL 区切りで path に書き込む
fn write_to(path: &Path, files: &[PathBuf]) -> Result<()> {
    let content = files
        .iter()
        .map(|file| file.to_string_lossy())
        .collect::<Vec<_>>()
        .join("\0");
    fs::write(path, content).with_context(|| format!("{} に書き込めませんでした", path.display()))
}
  • .collect::<Vec<_>>() の ::<> は「ターボフィッシュ」と呼ばれる書き方です。何に集めるかを型で指定し、_ の部分はコンパイラに推論させます。
  • .with_context(|| ...) は、エラーが起きたときだけメッセージを組み立てます。format! を使うときは .context() より無駄がありません。

/// "3" → Some((3, 3))、"2-4" → Some((2, 4))、それ以外 → None
fn parse_range(arg: &str) -> Option<(usize, usize)> {
    // 数字とハイフン以外が含まれていたら番号ではない
    if arg.is_empty() || !arg.chars().all(|c| c.is_ascii_digit() || c == '-') {
        return None;
    }

    match arg.split_once('-') {
        Some((start, end)) => {
            let start: usize = start.parse().ok()?;
            let end: usize = end.parse().ok()?;
            if start <= end {
                Some((start, end))
            } else {
                None
            }
        }
        None => {
            let n: usize = arg.parse().ok()?;
            Some((n, n))
        }
    }
}

/// 番号の引数をファイルパスに置き換える
/// 範囲外の番号や番号でない引数は、そのまま残す
pub fn expand(args: &[String], files: &[String]) -> Vec<String> {
    let mut result = Vec::new();

    for arg in args {
        match parse_range(arg) {
            Some((start, end)) if start >= 1 && end <= files.len() => {
                result.extend_from_slice(&files[start - 1..end]);
            }
            _ => result.push(arg.clone()),
        }
    }

    result
}

コードの読み方

  • start.parse().ok()? は3段階です。parse() が Result を返し、.ok() で Option に変換し、? で「None ならこの関数から None を返す」。Option を返す関数の中でも ? が使えます。
  • Some((start, end)) if start >= 1 && end <= files.len() => は「Some で、かつ条件を満たすとき」だけマッチします（マッチガード）。
  • &files[start - 1..end] はスライスです。番号は1始まり、配列の添字は0始まりなので - 1 します。..end は end を含みません。
  • +3 を弾くチェックがあるのは、"+3".parse::<usize>() が成功してしまうからです。先にテストを書いていたおかげで、この落とし穴に気づけます。試しに先頭の if を消して cargo test を実行してみてください。
  • .status() は .output() と違い、子プロセスの入出力をそのまま端末につなぎます。vim のような対話的なコマンドも動きます。

/// alias を実行する。args[0] が alias 名、残りが追加の引数
pub fn run(args: &[String]) -> Result<i32> {
    let (name, rest) = args.split_first().context("alias 名を指定してください")?;

    match name.as_str() {
        "gs" => {
            status::run()?;
            Ok(0)
        }
        "ge" => exec::run(rest),
        _ => {
            let alias = find(name).with_context(|| format!("不明な alias です: {name}"))?;

            let rest = if alias.expand {
                expand::expand_with_cache(rest)?
            } else {
                rest.to_vec()
            };

            let mut git_args: Vec<String> = alias.args.iter().map(|arg| arg.to_string()).collect();
            git_args.extend(rest);
            exec::run_command("git", &git_args)
        }
    }
}

/// alias 名のシンボリックリンクを dir に作成する
pub fn install(dir: &Path, force: bool, skip: &[String]) -> Result<()> {
    let exe = env::current_exe().context("gsct の実行ファイルの場所を取得できませんでした")?;
    fs::create_dir_all(dir).with_context(|| format!("{} を作成できませんでした", dir.display()))?;
    let dir = fs::canonicalize(dir)?;
    let path_var = env::var_os("PATH").unwrap_or_default();

    let names = aliases::SPECIAL
        .iter()
        .map(|(name, _)| *name)
        .chain(aliases::ALIASES.iter().map(|alias| alias.name));

    for name in names {
        if skip.iter().any(|s| s == name) {
            println!("skip     {name}（--skip で指定）");
            continue;
        }

        let link = dir.join(name);

        // すでに同じ名前のファイルがある場合
        if link.symlink_metadata().is_ok() {
            if fs::read_link(&link).ok() == Some(exe.clone()) {
                println!("exists   {name}");
                continue;
            }
            if !force {
                eprintln!("skip     {name}（{} が既にあります）", link.display());
                continue;
            }
            fs::remove_file(&link)?;
        } else if let Some(found) = find_in_path(name, &path_var, &dir) {
            // PATH 上に同じ名前のコマンドがある場合
            if !force {
                eprintln!(
                    "skip     {name}（既存のコマンド {} と衝突します）",
                    found.display()
                );
                continue;
            }
        }

        symlink(&exe, &link)
            .with_context(|| format!("{} を作成できませんでした", link.display()))?;
        println!("created  {}", link.display());
    }

    Ok(())
}
